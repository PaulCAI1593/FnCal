## 2 MCP 三工具（`code/app/api/mcp.mjs`）

| 工具 | 入参 | 直接模式返回 | 提案模式返回 |
| --- | --- | --- | --- |
| `create_tag` | `name`（必填，1–12 字）、`emoji?`（1 字素）、`groupId?` | `{ ok:true, mode:'direct', tag }` | `{ ok:true, applied:false, mode:'proposal', proposal }` |
| `update_tag` | `tag`（id 或名称，必填）、`emoji?`、`name?`、`groupId?` | 同上，`tag` 为更新后 | 同上，proposal 带 `tagId` / `before` / `after` |
| `delete_tag` | `tag`（id 或名称，必填） | `{ ok:true, mode:'direct', removed:{id,name}, affected }` | 同上，proposal 带 `tagId` / `before` / `affected` |

实现要点：

- 三个工具经 `toolsFor()` 注册，**与 `hasWritableCalendar` 无关**：只读凭据也列出这三个工具，行为由 `canTagWrite` 决定。
- 提案模式**不写注册表**，只建提案（`createProposal` 标签分支）。
- 直接模式直接调 `tagStore` 的 `create` / `update` / `remove`（`createTag` / `updateTag` / `deleteTag` → `tagWriteOrPropose`），不另写逻辑。
- 错误映射 `tagErrorOf(err)`：`TAG_NAME_DUPLICATE` / `GROUP_NAME_DUPLICATE` → 409 `tag_exists`；`TAG_NOT_FOUND` / `GROUP_NOT_FOUND` → 404 `tag_not_found`；`TAG_NAME_TOO_LONG` 等 → 400 `invalid`；提案过期 / 被改 → 409 `tag_changed`。
- 工具错误不抛 RPC 错误，走 `tagToolFailure`（`isError:true` + `structuredContent { code, message }`），与既有失败文本风格一致。
- 工具描述写明「受凭据标签权限控制，可能是提案」。

## 3 提案（`code/app/lib/ai-service.mjs` + `code/app/lib/ai-store.mjs`）

三个 action 与 payload：

| action | payload |
| --- | --- |
| `tag_create` | `{ tag: { emoji, name, groupId } }` |
| `tag_update` | `{ tagId, before: { emoji, name, groupId }, after: { emoji?, name?, groupId? } }` |
| `tag_delete` | `{ tagId, before: { emoji, name }, affected }` |

- 复用现有 24 小时过期、`pending/accepted/rejected/expired` 状态与 `decidedBy`。
- 受理时用 `before` 复核：`tag_update` / `tag_delete` 先 `tags.resolve(tagId)`，emoji 或 name 与 `before` 不一致 → `tagChanged()`（409 `tag_changed`，提示重新发起）。
- `list_proposals` / `decide_proposals` 支持这三种 action；标签提案跳过 `calendarId` / `uid` / 可见性校验（标签全局可见），受理走 `acceptTagProposal`。
- 卡片数据 `tagProposalCard(action, before, after)`（`ai-store.mjs`）：新建 `{kind:'create', emoji, name, groupId}`；编辑 `{kind:'update', before:{emoji,name}, after:{emoji,name}}`；删除 `{kind:'delete', emoji, name, affected}`。
- 用户侧 `/api/v1/ai/proposals` 映射新增 `tagId` 与 `tag`；标签提案 `calendarExists = true`，避免卡片误显示「日历已删除」（`code/app/api/ai.mjs:324`、`:345`）。

## 8 口径偏差（实现上绕不开，未自行改规格）

| # | 偏差 | 位置 | 原因 / 影响 |
| --- | --- | --- | --- |
| 1 | 标签提案标题不剥前导 emoji | `code/web/src/js/proposals-panel.js` `proposalDisplayTitle()` | 事件提案按惯例剥前导图标；标签新建卡的标题就是 `emoji + 名称`，剥掉会丢图标。仅标签提案走例外，其他动作不变。 |
| 2 | 标签提案 `calendarExists = true`，`calendarId` 为空 | `code/app/api/ai.mjs:345`；`proposals-panel.js` | 规格的提案复用现有卡片，而现有卡片按 `calendarId` 判「日历已删除」。标签提案没有目标日历，若按空 id 判会显示错误提示。 |
| 3 | 只读凭据的标签三行**不禁用** | `code/web/src/js/ai-settings.js:1046-1049` | 与规格 §2.1「与日历档位无关」一致；只跟 AI 接入开关。旧写 / 删行在无写档时禁用的逻辑未动。 |
| 4 | 标签名上限 12 字，不是规格写的 20 字 | `code/app/lib/tags.mjs:23`（既有 `TAG_NAME_MAX = 12`，本版未改） | 注册表是 0.7.x 已发布行为，改名上限属公开行为变更，超出本版范围；MCP 工具按注册表实际上限（12）执行并在描述里写明。若要 20 字需另开版本改注册表与网页输入限制。 |
