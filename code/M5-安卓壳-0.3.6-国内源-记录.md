## 三、B apkCn 与下载回退

清单字段（`UpdateChecker.kt:84 Manifest.apkCn`，`:201 parse()`）：

- 可缺省；缺省时 `apkCn = null`，下载只走 GitHub 包，行为与 0.3.5 相同。
- 只接受 `https://` 开头的单行地址；字段坏了按缺省处理，不让整条清单失效。

下载顺序（`UpdateChecker.kt:66 downloadTargets()`）：

| 第 1 次 | 第 2 次（失败一次后） | 落盘文件名 |
| --- | --- | --- |
| `apkCn`（Gitee 附件） | GitHub Release `apk` | 两次都用清单里的 `apk` |

- Gitee 附件缺失时只有 GitHub 一个目标，失败一次即报错。
- 文件统一用清单 `apk` 命名；不再有 `-cn` 次名，也不再经 `gh-proxy.com`。
- 两次都失败才显示失败，带 DownloadManager 原因码（真正结束下载的那次；它为 0 时退回第一次的原因，`AboutActivity.kt:463-474`）。
- 版本校验不变：安装前仍按 versionCode 比对包内版本，文件名不参与判断。
- 本地已有包检查（`AboutActivity.kt:304`）只查清单名；清理（`:320 cleanBeforeDownload()`）也只删清单名。
- 重定向链（Gitee 302 ×2 到 foruda.gitee.com）由 DownloadManager 跟随，不自带 UA 或 header。
