# impeccable 结论 · 0.6.11 日程列表节日 / 节气颜色与图标

范围：日程列表日期列（色与图标）、日期列不折行、以及「节日 / 节气」在全界面的
颜色与图标一致性核对。

## 一、A · 颜色与图标是同一套语义

「节日」是一个语义（公共假日，flag），「节气」是另一个语义（sun）。用户四条口径里
最要紧的是第 4 条：**图标什么颜色，文字就什么颜色**。

- 反模式：给图标单独写一次 `color: var(--accent)`。节日色是主题色，节气色是主题色
  反色；一旦图标写死主题色，节气就必然错色。0.6.10 的「小雪是蓝色」正是这个原因。
- 做法：图标统一 `color: currentColor`，颜色只写在容器上（节日 `--accent`、
  节气 `--term-ink`）。这样以后换主题、换对比度方案，图标自动跟随，不会再出现
  「文字对了、图标错」或反过来。
- 结论：颜色与图标不是两套样式，是同一套语义的两个出口。

## 二、B · 缺图标不是「少画一个」，是数据结构丢了信息

旧 `holidayOn()` 只回标题字符串，日期列无从判断节日还是节气，只能一律画主题色，
也画不出对应图标。改成返回叠加项对象后，`isTerm` 成为唯一判断源，类名、图标、
aria-label 三处同源，不会再各自猜。

- 教训：界面缺一个字段时，先看上游是不是把对象降级成了字符串。

## 三、C · 单行不是「尽量」，是硬约束

「11月」被折成「11」+「月」，是因为浏览器允许在数字与汉字之间断行，而日期列只有
96px。`white-space: nowrap` 把它变成不可能，而不是「大多数情况不会」。
窄档只降一档字号（12 → 11px）并收 1% 字距，不动列宽、不省月份、不改文案格式。

- 教训：需要「永远不断」的地方，用 CSS 禁止，而不是调宽度让它刚好够。

## 四、一致性核对的价值

把六个界面列成一张表之后，发现详情卡的节日图标一直是灰色（`--text-3`），和月视图、
全天条、日程列表都对不上。这不是 0.6.11 新引入的，而是没人一次看全过。
这次一并改成 `--accent`，节气的反色不变。

- 教训：「颜色各视图统一」这类要求，必须落成一张可核对的表，否则总有一处漏。

## 五、check_design 复跑

`check_design` 在日程列表 320 / 393 / 430 / 1280 四档共报 47 条，全部是既有项：

- 320 顶栏「2026年11月」被切 3px（顶栏宽度问题，非本次范围）；
- 事件标题在窄档换行（内容长度所致，产品允许）；
- 迷你月历「其它月」数字 2.79:1（0.6.9 之前就存在）；
- 点击区 < 44px、一屏 8 种字号。

本次改动范围内 **0 条新增**；`agenda__date-dow` 没有任何截断、换行或横向溢出项。
