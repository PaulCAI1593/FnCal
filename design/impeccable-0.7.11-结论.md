# impeccable 0.7.11 结论

范围：0.7.11「AI 标签权限」的网页端改动 —— 设置 → AI 权限 → 凭据编辑新增「标签」组三行（新建 / 编辑 / 删除 × 提案 / 直接通过），以及「AI 提案」列表的三类标签提案卡（新建 / 编辑 / 删除）。本文件记录设计技能调用、判断、验证与偏差。

## 一、技能调用

- `impeccable detect --json`（workdir `projects/CalDAV/code`）→ `[]`、`EXIT=0`（开工基线）。
- `impeccable detect --json code/web/src/js/ai-settings.js code/web/src/js/proposals-panel.js code/web/src/i18n/zh-CN.js`（workdir `projects/CalDAV`，收口）→ `[]`、`EXIT=0`。
- `impeccable context --target code/web/src/js/ai-settings.js --target code/web/src/js/proposals-panel.js` → `EXIT=0`，报 `NO_PRODUCT_MD` / `PRODUCT_INIT_REQUIRED`；本仓库自 0.4.x 起均为既有 UI 上的增量，按技能说明不阻塞。
- 设计判断全部落在既有令牌与既有组件上：没有新增颜色、字号、圆角、阴影、动效；`--fs-sm`、`--r-md`、`--shadow-md`、`--surface`、`--border` 未动。

## 二、设计判断

### 2.1 三行权限放在哪、长什么样

| 判断 | 结论 | 理由 |
| --- | --- | --- |
| 位置 | 「操作方式」块之后、「代办批准」块之前 | 三行都是凭据级的操作口径，跟写 / 删档同一组语义；放在代办开关前，用户从上到下读「能做什么 → 怎么执行 → 谁批准」。 |
| 组件 | 复用 `segmentedRadioGroup` + `ai-mode-row` + `block()` | 与写模式、删除模式完全同构，用户不用学第二套控件；窄屏下分段控件已有折行规则。 |
| 选项顺序 | 「直接通过 / 提案」 | 与既有写模式、删除模式一致；规格写「提案 / 直接通过」是列举，不是顺序要求。若强行调换，同一页会出现三种顺序，反而更难扫读。 |
| 默认值 | 提案 | 规格 §2.1；旧凭据无字段即提案，打开编辑器看到的就是提案。 |
| 危险提示 | 切「直接通过」弹二次确认（`danger: true`），并在行下加一行 `ai-danger-hint` | 「直接通过」会让 AI 不经人确认就改全局标签，和删除模式同级的风险；沿用既有的红色提示与确认弹层，不新造警示样式。 |
| 禁用口径 | 只看 AI 接入开关，不看日历写档 | 标签是全局注册表，与日历 grants 无关（规格 §2.1）。旧写 / 删行「无写档则禁用」的逻辑未动。 |

### 2.2 三类提案卡

| action | 卡片主体 | 影响行 |
| --- | --- | --- |
| `tag_create` | `emoji + 名称`（标题保留 emoji） | 作用域文案「标签」 |
| `tag_update` | 「旧 → 新」，emoji 与名称各一行 | 作用域文案「标签」 |
| `tag_delete` | `删除 名称` | 「影响 N 条日程 / 任务」（`affected`） |

- 卡片沿用现有提案卡的徽标（凭据名 │ 动作词）、状态、过期时间、批准 / 驳回按钮；动作词新增「新建标签 / 编辑标签 / 删除标签」，长度与「修改」「删除」同量级，徽标不换行。
- 标签提案没有目标日历：`calendarExists` 固定为 `true`，避免卡片误显示「日历已删除」。
- 标题不剥前导 emoji：事件提案按惯例剥图标，标签新建卡的标题本身就是 `emoji + 名称`，剥掉会丢图标；例外只作用于标签 action。

## 四、偏差

1. 标签提案标题不剥前导 emoji —— 见 §2.2，属有意的视觉例外。
2. 只读凭据三行不禁用 —— 与规格 §2.1 一致，不是视觉偏差；但与同页写 / 删行「无写档即禁用」形成对照，用户可能问「为什么这三行能改」。已在行下 hint 里说明「标签是全局设置，与日历权限无关」。
3. 选项顺序「直接 / 提案」与规格文字列举顺序不同 —— 为与同页既有组件一致，判断见 §2.1。
